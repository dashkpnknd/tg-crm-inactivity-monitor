# Telegram CRM inactivity monitor

Сервис читает активность групп из авторизованного Telegram-аккаунта и уведомляет о трёх днях без сообщений в отдельной группе **CRM**. В клиентские чаты он никогда не пишет.

## Как это работает

1. Бот получает `/setup` в группе CRM. Автор этой команды становится администратором настройки.
2. Администратор пишет `/start` боту в личные сообщения.
3. Бот запрашивает одноразовый код для аккаунта, который отслеживается. Код и облачный пароль (если включён) принимаются только временно и бот пытается удалить такие сообщения сразу после обработки.
4. Сервис принимает новые сообщения и раз в сутки сверяет список групп. Обычные сообщения команды и клиентов считаются активностью. Сообщения `@avitoReportStat_bot` не сбрасывают таймер. Если в чате не было учитываемых сообщений три дня, бот отправляет одну карточку в CRM. Пока нет новой активности, повторов нет.
5. Кнопка **Открыть чат** открывает исходную группу. Кнопка **Не отслеживать** исключает её из будущих проверок. Нажать её может любой участник группы CRM.

После учитываемого сообщения чат начинает новый цикл: открытая карточка удаляется, а новое уведомление возможно только после следующих трёх дней тишины.

### Ограничения для безопасности аккаунта

Сервис работает с постоянной Telegram-сессией с одного сервера и не рассылает сообщения от имени аккаунта. При ежедневной сверке, если последнее сообщение оставил не клиент, он читает историю этого чата до первого сообщения клиента или до границы трёхдневного окна. При ответе Telegram `FloodWait` сервис выдерживает назначенную Telegram паузу и не повторяет запрос раньше времени.

## Первый запуск на сервере

Никогда не добавляйте реальные токены, пароли или `*.session` в Git.

```bash
git clone https://github.com/dashkpnknd/tg-crm-inactivity-monitor.git
cd tg-crm-inactivity-monitor
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f
```

В `.env` заполните:

- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — приложение с [my.telegram.org/apps](https://my.telegram.org/apps);
- `KSUSHA_PHONE` — номер отслеживаемого аккаунта в международном формате;
- `BOT_TOKEN` — новый актуальный токен из `@BotFather`.

Затем отправьте `/setup` в группе CRM и `/start` в личном диалоге с ботом. Бот запросит код, выполнит вход и начнёт первую проверку.

## Управление

- `/setup` — подключить текущую группу как место CRM-уведомлений. Доступно создателю первоначальной настройки.
- `/start` — запросить код и подключить аккаунт в личном диалоге с ботом.
- **Не отслеживать** — исключить чат из мониторинга.

## Безопасность

Сессия Telegram и SQLite-база размещаются в `data/`, которая не попадает в Git. Токен бота и API-ключи хранятся только в `.env` на сервере.

## Связи и границы проекта

Монитор отслеживает клиентские Telegram-группы и сообщает о длительном отсутствии сообщений. Он не запускает кампании рассылки; это отдельный сценарий от `tg-activity-sender` и `tg-follow-up`.
